# Documentation research ও নির্বাচিত strategy

**গবেষণার cutoff: ৫ নভেম্বর ২০২৬।** আন্তর্জাতিক বিচারকদের জন্য ইংরেজি README ও মূল্যায়নের নথি; বাংলা project introduction ও এই সিদ্ধান্তপত্র সহায়ক। নিচের primary pages এই session-এ খোলা হয়েছে। Undated page-কে নতুন ২০২৬ প্রকাশনা বলা হচ্ছে না। Search snippet ও live page/raw file-এর সামান্য পার্থক্যকে ঐতিহাসিক সত্য হিসেবে ব্যবহার করা হয়নি।

## কী প্রয়োজন, আর কী সুপারিশ

এই প্রতিযোগিতা অফিসিয়ালি বাংলাদেশের শিক্ষার্থীদের solo B2C buildathon; panel-এ আন্তর্জাতিক বিচারক আছেন। Hosted app ও সর্বোচ্চ পাঁচ-slide presentation মূল submission; English video সুপারিশকৃত, repository ঐচ্ছিক। App-এর near-top organizer sticker আলাদা requirement। কোনো README, সুন্দর repository বা local video এগুলোর বিকল্প নয়। বর্তমান page-এ deadline header/body-তে অমিল আছে। [Official rules](https://yunet-aignite26.devpost.com/rules)

README-তে architecture diagram, test evidence, screenshots, AI/data boundaries বা contribution guide রাখা এই event-এর ঘোষিত বাধ্যতামূলক তালিকা নয়। এগুলো বিচারকের মূল্যায়ন সহজ করার জন্য আমাদের নির্বাচিত supporting evidence। অন্য প্রতিযোগিতার Microsoft-service requirement বা video cap এখানে প্রয়োগ করা যাবে না।

## কোডবেস থেকে পাওয়া প্রধান অসংগতি

পুরোনো judge guide-এ floating widget, ১৩৪-test scorecard, স্বয়ংক্রিয় notice dispatch ও zero-hallucination দাবি ছিল। Provider register Google-first inference, universal retention/encryption এবং pretrained E5 নিয়ে current implementation-এর সঙ্গে না-মেলা বক্তব্য দিত। README ও admin guide আবার পরবর্তী seeded preview/admin evaluation পরিবর্তনের আগের অবস্থায় ছিল।

কোডে বর্তমান workspace retrieval স্পষ্টত `dense_enabled=False`; legacy E5 adapter deterministic hash তৈরি করে। Community নতুন post প্রত্যাখ্যান করে, কিন্তু seeded feed/comment/reaction আছে। Judge-admin launcher real global roles দেয় এবং environment gate নেই। তাই polish-এর আগে claim correction অপরিহার্য। [বিশদ audit](CODEBASE_DOCUMENTATION_AUDIT_2026-11-05.md)

## নির্বাচিত reading experience

১. **প্রথম screen:** Ebarki, এক বাক্যে কাজ, live/demo/deck links, event graphic ও solo builder। Mock links আপনার নির্দেশ অনুযায়ী দৃশ্যমান placeholder।

২. **প্রথম বাস্তব উদাহরণ:** ৳৫,৫০০ বনাম ৳৫,০০০; দ্বিতীয় receipt-এ অমিল ব্যাখ্যা। Actual fictional-case screenshot। কোনো fabricated recovery KPI নয়।

৩. **নিজে পরীক্ষা:** ছোট judge walkthrough, expected outcome, failure হলে কী দেখতে হবে। Consumer ও admin session আলাদা।

৪. **Engineering depth:** কোন stage model, কোনটি parser/rule; consent, ownership, uncertainty, version guard এবং source links।

৫. **প্রমাণ:** Test count-এর সঙ্গে scope/date; provider receipt-এর সঙ্গে error/retry; browser capture ও complete acceptance আলাদা।

৬. **Supporting docs:** Setup, feature guide, API, architecture, providers, privacy, admin, evidence, contribution/security এবং final submission checklist।

## পেশাদার দেখানোর নির্দিষ্ট নিয়ম

- Original restrained SVG cover, একটি flagship screenshot, চারটি supporting screenshot; ছোট unreadable collage নয়।
- Event graphic unchanged; official event link; exact download provenance-এর সীমা credits-এ।
- Fake stars, fake CI-pass badge, made-up accuracy বা “production-ready” stamp নয়।
- নতুন features source দিয়ে যাচাই; পরিকল্পনার তালিকাকে shipped capability বলা নয়।
- মূল README সংক্ষিপ্ত entry হিসেবে থাকবে; সব API table বা raw QA dump সেখানে নয়।
- একই URL registry, relative links, meaningful alt text ও rendered desktop/mobile QA।
- কোনো license স্বয়ংক্রিয়ভাবে আরোপ নয়; third-party notices অক্ষুণ্ণ।

## পরবর্তী সর্বোচ্চ মূল্যমানের কাজ

এই নথির পর owner-এর প্রধান কাজ তিনটি আসল public URL বসানো এবং required artifacts anonymous browser-এ পরীক্ষা। তার পাশাপাশি privileged demo gate ও public seed provenance ঠিক করা deployment-এর শর্ত। Real user research এখনো প্রমাণিত নয়; qualified reviewer-সহ consented pilot-এ evidence-reconciliation ও preparation accuracy মাপা যেতে পারে। এগুলো ভবিষ্যৎ সুপারিশ, অর্জিত ফল নয়।
